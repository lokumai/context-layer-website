# Semantic Conventions

Single reference for every cross-cutting naming and field convention in the workspace. If a new service or agent needs to emit events, logs, or correlation headers, it must match these exactly.

## Correlation ID

- Header: `X-Correlation-ID`
- Format: UUID v4 (hex with hyphens, lowercase)
- Lifetime: per-request; propagated across every hop
- Generated by: `api-gateway` if absent on inbound; by the requesting service otherwise
- Exposed by: every service in every log record, every span tag, every outbox row

## Trace Propagation

- Standard: B3 (Zipkin)
- Headers: `X-B3-TraceId`, `X-B3-SpanId`, `X-B3-ParentSpanId`, `X-B3-Sampled`
- Initialized in: `common.tracing.setup_tracing()`
- Instruments: FastAPI, SQLAlchemy, httpx, aio-pika

## Log Schema

Every log line is JSON with:

```json
{
  "timestamp": "2026-04-22T14:08:41.234Z",
  "level": "INFO",
  "service_name": "offering-service",
  "correlation_id": "b4e0c...-...",
  "trace_id": "9e...",
  "span_id": "1f...",
  "event": "offering.publication.initiated",
  "offering_id": "uuid",
  "message": "Offering publication saga started"
}
```

Additional fields may be added per log line. `message` is the human-readable anchor; `event` is the machine anchor.

## Event Topics

| Topic | Publisher | Payload envelope |
|---|---|---|
| `resource.characteristics.events` | characteristic-service | `{ event_id, event_type, aggregate_id, timestamp, correlation_id, entity_version, payload }` |
| `resource.specifications.events` | specification-service | same |
| `commercial.pricing.events` | pricing-service | same |
| `product.offerings.events` | offering-service | same |

### Event Type Naming

Past tense, PascalCase, noun + verb:

- `CharacteristicCreated`, `CharacteristicUpdated`, `CharacteristicDeleted`
- `SpecificationCreated`, `SpecificationUpdated`, `SpecificationDeleted`
- `PriceCreated`, `PriceUpdated`, `PriceDeleted`, `PriceLocked`, `PriceUnlocked`
- `OfferingCreated`, `OfferingUpdated`, `OfferingPublicationInitiated`, `OfferingPublished`, `OfferingPublicationFailed`, `OfferingRetired`

## Error Codes

Uppercase snake case. The stable set today:

- `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `VALIDATION_ERROR`, `LOCKED`, `SERVICE_UNAVAILABLE`, `INTERNAL_ERROR`

New codes require an ADR in `docs/adr/`.

## Database Tables

- Business tables: plural, snake_case (`characteristics`, `specifications`, `prices`, `offerings`, `users`).
- Outbox table: always `outbox`.
- Cache tables: prefix `cached_` (e.g., `cached_characteristics`).

## FastAPI Routing

- Base path: `/api/v1` on every service.
- Resource paths: plural, snake-case (`/characteristics`, `/specifications`, `/prices`, `/offerings`, `/store/offerings`).
- Action sub-paths under a resource use kebab-case verbs (`/offerings/{id}/publish`, `/offerings/{id}/retire`).

## Python Module Layout

```
src/
  domain/        # pure
  application/   # use cases
  infrastructure/  # frameworks + adapters
  main.py        # FastAPI app
```

## Testing Layout

- `tests/unit/` — pure, no I/O
- `tests/integration/` — testcontainers
- `tests/component/` — FastAPI + httpx.AsyncClient with mocked peers
- `tests/e2e/` (workspace root only) — end-to-end against Docker Compose
